# 分析增强与棋手库对局筛选设计

## 目标

在现有竞技成长型分析流程中加入三项能力：

1. 历史页筛选出双方都在棋手库中的对局。
2. 分析页输入临时对手或选择已有棋手，预测当前棋手的胜率。
3. 分析页展示当前棋手与棋手库对手的历史交手胜负。

功能面向当前选中的棋手，所有结果都从现有统一对局账本即时计算。编辑、删除、撤销或切换棋手后，结果随当前状态更新。

## 已确认的产品交互

### 历史筛选

历史页保留现有段位、结果、日期和旧历史筛选，并增加“对局类型”筛选：

- 全部：显示当前棋手的全部历史。
- 临时对手：显示 `kind == NATIVE && opponentPlayerId == null` 的对局。
- 棋手库对局：显示 `kind == NATIVE && opponentPlayerId != null` 的对局。

筛选作用于当前棋手的只读投影，不写回数据库。棋手库对局在当前棋手视角显示，对手姓名来自棋手库，胜负沿用投影后的结果。

### 胜率预测

分析页新增“胜率预测”卡片。卡片显示当前选中棋手的实时 ELO，并提供两种对手模式：

- 临时对手：输入 1–9 段和最近不超过 20 盘战绩，例如 `11-8`。
- 棋手库：从除当前棋手外的已有棋手中选择。

输入有效后即时显示对手 ELO、当前棋手胜率、对手胜率，以及当前棋手胜负两种结果的预计 ELO 变化。未输入完整对手时显示引导状态；战绩格式或范围不合法时显示错误提示，不影响历史数据。

预测使用当前等级分预期公式：

```text
P(当前棋手胜) = 1 / (1 + 10 ^ ((Ropp - Rself) / 400))
```

临时对手使用当前 `elo-v3` 规则估分，棋手库对手使用其当前实时 ELO。预测是只读计算，不会生成对局或改变等级分。

### 棋手库对局汇总

分析页新增“棋手对局”卡片，只统计双方都有棋手库档案的对局。按对手分组显示：

- 对手姓名；
- 胜-负；
- 总盘数；
- 胜率。

点击对手行展开该对手的逐盘结果序列，按时间顺序显示胜负和日期。没有棋手库对局时显示空状态，并说明需要先使用“已有棋手”模式记录对局。

## 领域与数据设计

不新增 Room 字段，不改变 `.goelo.json` schema，也不保存分析快照。

- `HistoryFilter` 增加对局类型枚举或等价字段，`filterMatches` 在现有条件上组合该条件。
- 统计层新增胜率预测结果模型，封装预期胜率、胜负预计分差和对手 ELO，复用 `scoreChange` 的 K=20 规则。
- 统计层新增棋手对局汇总模型，使用 `AppState.forPlayer(currentId)` 的视角投影，按 `opponentPlayerId` 分组。
- 分析页接收完整账本和当前棋手投影：完整账本用于选择棋手库对手和读取实时 ELO，投影用于当前棋手的历史、胜负和日期。
- 所有计算均为纯函数或 Compose 局部状态，不引入网络、账号或后台同步。

已有 `elo-v1/v2/v3` 规则和历史重放逻辑保持不变。新功能只读取重放后的状态，因此历史编辑、删除和双方对局同步重算会自然反映到分析结果。

## 空状态与错误处理

- 棋手库只有当前棋手时，棋手库预测模式显示“暂无其他棋手”。
- 临时对手输入为空时不显示数值结果，只显示输入提示。
- `rank` 不在 1–9、战绩超过 20 盘、胜负格式错误时，显示现有统一输入错误样式。
- 没有棋手库对局时，交手汇总显示空状态；临时对手对局不计入交手汇总。
- 历史筛选条件非法时保留当前页面并显示错误，不修改数据。

## 测试与验收

### 单元测试

- 历史类型筛选能正确区分临时对手和棋手库对局，并可与段位、结果、日期组合。
- 当前棋手从双方对局的另一侧查看时，胜负和分差方向正确反转。
- 胜率预测在临时对手和棋手库对手两种输入下返回相同的预期公式结果。
- 胜负预计分差与现有 `scoreChange` 保持一致。
- 棋手对局汇总正确计算每位对手的胜、负、总盘数和胜率。
- 空棋手库、空历史和非法输入不会抛出未处理异常。

### UI 验收

- 历史页能选择“棋手库对局”，结果数量和列表内容正确。
- 分析页能切换两种预测对手，输入变化会即时更新结果。
- 分析页能看到每位棋手库对手的历史胜负，并展开逐盘结果。
- 切换当前棋手后，预测主体、历史筛选结果和交手统计都切换到新视角。
- 完整 JVM 测试、Lint 和 Android 测试代码编译通过。
